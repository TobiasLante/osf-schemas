# sources/rest/erp-operations-segments.json — history and reasoning

Moved out of `sources/rest/erp-operations-segments.json`, where each field holds its first sentence. The JSON says what a thing is; this file keeps why it became that.

## description (1.0.0, Welle 12, 25.09.2026)

Routing steps (ISA-95 OperationsSegment) from sim-v5 erp-operations GET /process-segments. Measured 25.09.2026: 588 rows, all distinct, ordered by process_segment_no. sim-v5 calls them process segments (PS-PART-A-10 PART_OF OPDEF-PART-A), but a step of one routing with sequence and planned duration is an ISA-95 OperationsSegment (owner 25.09.). Not bound, never invented: process_segment_ref (sim-v5 serves process_segment_code, e.g. VORMONTAGE, which is a code, not a ProcessSegment key), material_ref (no column), equipment_class_ref (unit_ref POOL-* is a machine pool; whether a pool is an EquipmentClass is not decided). Hence only PART_OF OperationsDefinition; FOR_PROCESS_SEGMENT, SPECIFIES_MATERIAL, SPECIFIES_EQUIPMENT stay without a source.

## description (1.1.0, Welle 13, 25.09.2026)

Owner 25.09. (Frage 1 "ja"): the ISA-95 edges of the OperationsSegment hang on this source, only as the tree releases them (`standard/validation/relationship-types.json` isa95, generated from B2MML 0700 in `isa95-edges.json`). Measured on .154 GET /process-segments 25.09.2026: 588 rows, 8 fields (process_segment_no, process_segment_code, name, operations_type, sequence, duration_planned_sec, operations_definition_ref, unit_ref).
- `FOR_PROCESS_SEGMENT` OperationsSegment -> ProcessSegment (B2MML `OperationsSegment.ProcessSegmentID`): column process_segment_code (588/588 set; 4 values VORMONTAGE, MONTAGE, PRUEFFELD, VERSAND) -> ProcessSegment.process_segment_no, target source erp-process-segments. This revises the 1.0.0 reading "a code, not a ProcessSegment key": ISA-95 identifies the reusable stage by exactly this ID, and every code carries one constant name and operations_type.
- `SPECIFIES_EQUIPMENT` OperationsSegment -> EquipmentClass (B2MML `OperationsSegment.EquipmentSpecification.EquipmentClassID`): column unit_ref (441/588 set, POOL-VORMONTAGE / POOL-ASSEMBLY_LINE / POOL-PRUEFFELD; VERSAND has none) -> EquipmentClass.equipment_class_id, target source erp-machine-pools. A pool is a named classification of equipment with its member list (GET /pools machineIds), which is what ISA-95 calls an Equipment Class (OPC 10030 ISA-95 Common Object Model §4, reference.opcfoundation.org/ISA-95/v100/docs/4: "Each instance of the Equipment Class defines a classification of equipment"). The catalogue's other target, Equipment (EquipmentID), does not fit: unit_ref names no single machine.
- `SPECIFIES_MATERIAL` OperationsSegment -> MaterialDefinition stays unbound: no column of /process-segments carries an article. The article sits on the OperationsDefinition (article_ref, 147/147); /api/arbeitsplaene (:38260) carries part_number per operation, but its operations are another identity set (routing_no AP-..., 0/147 equal to an operations_definition_no), so no segment row gets its article from it without a derived join. Open: sim-v5 serves the article on /process-segments.
