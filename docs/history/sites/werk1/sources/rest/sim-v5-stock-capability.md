## description (1.0.0, core 6.2.0 M-34, owner 13.11.2026 "eigener Datensatz jetzt")

sim-v5 api-erp GET /api/stock-capability (#1280, LIVE 13.11.2026): one row per part_number × warehouse × capability_type from erp.stock — Total = qty_on_hand + qty_blocked, Unattainable = qty_blocked, Committed = qty_reserved (without open BOM demand, as /api/articles), Available = max(0, Total − Unattainable − Committed); unit = the article's unit, updated_at = erp.stock.updated_at (mapped to start_time: the capability holds from then). id = <part_number>|<warehouse>|<capability_type>, keyset after_id in byte order (COLLATE "C"), limit ≤ 5000. Stock is no property of the material definition (ISA-95 / B2MML MaterialCapability, OperationsCapability) — the article's stock_* fields are no longer mapped, and core 6.2.0 removes them (SMProfile-Article 3.0.0, owner 14.11.2026: no deprecation window; movedAttributes → SMProfile-OperationsCapability quantity). Note: erp.stock never blocks (qty_blocked is 0 on PROD); blocked stock exists only on the quants (WMS), so Unattainable is 0 from the ERP book. The warehouse is a location (B2MML StorageLocation, ResourceLocationType), not an edge.
