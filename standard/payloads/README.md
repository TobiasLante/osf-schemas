# Payloads (v1.0.0)

GENERATED by i3x-v5 packages/schemas-ci/gen-payloads.mjs from `standard/profiles/**` and `standard/sync/uns-convention.json` 1.2.0; do not edit by hand.
When a profile changes, regenerate (`--check` is part of check-next).

| transport | format | file |
|---|---|---|
| NATS, MQTT | JSON Schema (draft-07) | `json/<folder>/<profileId>.payload.json` |
| Kafka | Avro | `avro/<folder>/<profileId>.avsc` (value schema, TopicNameStrategy) |

Two shapes (`envelope.schema.json`), from the convention:

- **signal** (categories machine; 2 profiles): one message per signal,
  `{element_id, attr, value, timestamp, delivery, msgId?}`. Every attribute of the machine is listed, edge ones included.
- **entity** (categories business, material, quality, equipment; 34 profiles): one message per source row,
  `{eventType, id, entity, timestamp, msgId, data}`; `data` carries the profile's attributes, inherited ones included.

**Telemetry and transactional are strictly apart.** Every attribute carries its profile `delivery`:

| delivery | subject | msgId |
|---|---|---|
| telemetry | `factory.{site}.{machine}.telemetry.{attr}` | not needed |
| transactional | `factory.{site}.{machine}.event.{attr}` · `business.{enterprise}.{sourceId}.{entity}.{eventType}.{id}` | required (Nats-Msg-Id / Kafka key: deduplication, nothing lost) |

Keys (`element_id`, `id`, the profile's key attribute) are subject tokens: no `+ # * > /` or space.
Abstract and retired profiles send nothing and have no payload; a category in neither world of the convention has none.
