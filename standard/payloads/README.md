# Payloads (v1.1.0)

GENERATED by i3x-v5 packages/schemas-ci/gen-payloads.mjs from `standard/profiles/**` and `standard/sync/uns-convention.json` 2.0.0; do not edit by hand.
When a profile changes, regenerate (`--check` is part of check-next).

| transport | format | file |
|---|---|---|
| NATS, MQTT | JSON Schema (draft-07) | `json/<folder>/<profileId>.payload.json` |
| Kafka | Avro | `avro/<folder>/<profileId>.avsc` (value schema, TopicNameStrategy) |

Two shapes (`envelope.schema.json`), from the convention:

- **signal** (categories machine; 2 profiles): one message per signal,
  `{element_id, attr, value, timestamp, delivery, msgId?}`. Every attribute of the machine is listed, edge ones included.
- **entity** (categories business, material, quality, equipment; 88 profiles): one message per source row,
  `{eventType, id, entity, timestamp, msgId, data}`; `data` carries the profile's attributes, inherited ones included.

Both may carry `b2m {verb, actionCode}` (optional; ISA-95 Part 5 as B2MML 0701 names it): a row is `SYNC` with the action code of its
eventType (created = Add, updated = Change, deleted = Delete), a transactional signal `SYNC Add`, telemetry none.

**Telemetry and transactional are strictly apart.** Every attribute carries its profile `delivery`:

| delivery | subject | msgId |
|---|---|---|
| telemetry | `factory.{site}.{entity}.{machine}.telemetry.{attr}` | not needed |
| transactional | `factory.{site}.{entity}.{machine}.event.{attr}` · `business.{enterprise}.{site}.{entity}.{sourceId}.{eventType}.{id}` | required (Nats-Msg-Id; on Kafka the key is the entity's kgIdProperty: deduplication, nothing lost) |

**Kafka: one topic per contract and site** (`<prefix>.{site}.{entity}`, TopicNameStrategy: the contract's Avro value schema under `<topic>-value`), telemetry
and transactional of a contract on the same topic; the message key is the entity's key (the profile's kgIdProperty, `x-kafka` of each `.avsc`).
The NATS subjects carry the same `{site}.{entity}` (a subscriber filters per contract); the streams stay per delivery.

Keys (`element_id`, `id`, the profile's key attribute) are subject tokens: no `+ # * > /` or space.
Abstract and retired profiles send nothing and have no payload; a category in neither world of the convention has none.
